# Metafetch's Exploration Gets a Status a Dashboard Can Group By

## Why Care?

[[2026-11-01_01]] made `metafetch/context-v/` an Open Knowledge Format bundle. This pass checks the same docs against the Context Vigilance Kit's baseline frontmatter. They already carried it, so the only change is one status word that a workflow dashboard wouldn't know how to group.

## What's New?

- **The folder-aware frontmatter exploration moves from `Exploration` to `Draft`.** `Exploration` isn't in the kit's status vocabulary; it maps to `Stub` or `Draft`, and a 300-line doc with two dated progress notes is not a stub.

## Under the Hood

- Part of the tree-wide OKF sweep; see the Context Vigilance Kit's plan, [[Retrofit-Every-Repo-to-OKF-Then-the-Kit-Frontmatter]].
- Every doc already had its `title`, dates, `authors`, `site_uuid`, and `hex_code`, so nothing was added and no IDs were minted. No tags, lists, or version keys needed normalizing.
- The edit was made by hand. No body line changed, no key was deleted, and no date moved.
- The two plans keep `Implementing`, a value already on the list.
