**A note about a tool can now show the tool.** Run **Fetch screenshots from website** and Metafetch captures the site in the note's `url`, saves the image in your vault, and embeds it under `## Screenshots`.

## Why Care?

Link cards tell a reader what a page is. A screenshot shows them. Our toolkit notes always had a place for screenshots and almost never had any in it, because capturing, saving, and embedding one by hand is a chore that loses to everything else.

## What's New?

- **Fetch screenshots from website.** Captures the page through [Microlink](https://microlink.io/), saves it to your attachments folder with the date in its name, and embeds it with a caption linking to the page.
- **No key needed** for about 50 screenshots a day. A Microlink key, under the existing Microlink setting, raises the limit.
- **Saved, not linked.** Microlink's image links expire, so the image is downloaded and kept in your vault.
- **Additive.** Existing screenshots stay, including ones Perplexed's screenshot search found, and the two commands are designed to be run together.

## Good to Know

- The capture is the top of the page at desktop width, not the full scrolling page.
- The command uses the note's `url`, or its only URL-valued property.

## Under the Hood

- `src/services/microlinkScreenshotService.ts` — `screenshot=true&meta=false`, with the same error handling and rate-limit message as Fetch via Microlink.
- `src/commands/fetchScreenshotIntoNote.ts` — download, `vault.createBinary` at the attachment path, and the embed via `generateMarkdownLink`, so it follows your link format.
- `src/utils/screenshotsSection.ts` — the `## Screenshots` writer: appends after existing images, replaces a placeholder, ignores headings inside code fences.
