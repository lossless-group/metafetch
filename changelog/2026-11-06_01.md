# Metafetch Screenshots a Website Into Your Note

## Why Care?

A note about a tool should show what the tool looks like. Our toolkit notes have a `## Screenshots` section for that, and it was almost always empty, because finding, saving, and embedding a screenshot by hand is exactly the chore nobody gets to.

Now it's one command.

## What's New?

- **Fetch screenshots from website.** Run it on any note with a `url`, and Metafetch captures that page, saves the image to your attachments folder as `linear-app-screenshot-2026-11-06.png`, and embeds it under `## Screenshots` with a caption saying where and when it was taken.
- **Free to start.** It uses [Microlink](https://microlink.io/), the service behind **Fetch via Microlink**: about 50 screenshots a day with no key, and more with one.
- **It adds, never replaces.** Screenshots you already have stay, including ones Perplexed found. A placeholder like "none publicly available" is replaced.

## Why Save the File?

Microlink hands back a link to the image, but that link expires. A note that embeds it would show a broken image within days. So Metafetch downloads the image and keeps it in your vault, where it belongs to you, syncs with the rest of the vault, and still works offline.

## Two Commands, Two Kinds of Screenshot

Perplexed 0.6.0 ships a command with the same name that works differently, and they're meant to be used together:

| | Metafetch | Perplexed |
|---|---|---|
| **What you get** | The homepage as it looks today | The product screenshots the company publishes |
| **How** | Microlink renders the page | Perplexity's image search, limited to the company's site |
| **Stored** | In your vault | Linked from the company's site |
| **Cost** | Free for about 50 a day | Your Perplexity key |

Both write to `## Screenshots` with the same rule, so running one after the other keeps both sets.

## Good to Know

- **Which URL:** the note's `url`, or its only URL-valued property when it has no `url`. With several and no `url`, the command asks you to add one.
- **The screenshot is the top of the page** at a desktop width, not the whole scrolling page.
- **Tested** by unit tests for the response parsing, file naming, and section writing.
